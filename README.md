## Запуск и проверка

Требуется Python 3.10+ (проверено на 3.11).

```sh
python -m pip install -r requirements.txt
# Создайте .env по образцу env_example.txt и заполните TOKEN и ADMIN_IDS.
python main.py
```

Регрессионные тесты без Telegram, внешних API и рабочей базы:

```sh
python -m unittest discover -s tests -v
```

Тесты используют SQLite в памяти и заглушки сетевых вызовов. Не используйте старый диагностический скрипт `test_db.py` как тестовый набор: он обращается к локальной БД.

## Приют для кошко-жен

Кошку можно временно сдать в приют за еду. В приюте она не голодает, не скучает и не пишет
уведомлений, а по истечении оплаченного срока возвращается домой автоматически.

| Команда | Действие |
|---|---|
| `/shelter` (`приют`) | Условия и статус своей кошки |
| `/shelter_place [дней]` (`сдать кошку [дней]`) | Сдать кошку в приют |
| `/shelter_extend [дней]` (`продлить приют`) | Продлить срок |
| `/shelter_take` (`забрать из приюта`) | Забрать раньше срока |
| `/shelter_list` (`список приюта`) | Кто сейчас в приюте |
| `/shelter_my` (`моя кошка в приюте`) | Как дела у своей кошки |

Цены и лимиты задаются в `config.py`: `SHELTER_PRICE_KORM_PER_DAY`,
`SHELTER_PRICE_RICE_PER_DAY`, `SHELTER_MAX_DAYS`, `SHELTER_RETURN_SATIETY_BONUS`.
Оплата идёт кормом (в приоритете) или рисом; списание и запись в приют выполняются
одной транзакцией, поэтому двойное списание при параллельных командах невозможно.

Если забрать кошку раньше срока, еда за **неиспользованные полные сутки** возвращается
тем же видом продукта. Неполные сутки не списываются: забрал через час — вернулось всё.
Бонус сытости тоже пропорционален времени в приюте, поэтому «сдал и сразу забрал» его не даёт.

Пока кошка в приюте, ежедневная бесплатная еда выдаётся уменьшенной
(`DAILY_FOOD_AMOUNT_IN_SHELTER` вместо `DAILY_FOOD_AMOUNT`): расход еды в приюте нулевой,
и полная выдача превращалась бы в бесконечный фарм.

## Обновление существующей установки

- Перед первым запуском обновлённой версии остановите бота и сделайте резервную копию SQLite (включая актуальный WAL, если он есть; предпочтительно через SQLite backup API).
- Изменения схемы применяются при запуске: существующие варны сохраняются, старая категория кошек мигрирует без потери доверия и браков, таблица приюта создаётся автоматически.
- База `users.db` теперь всегда открывается рядом с `database.py`, а не относительно текущей директории запуска. Если ранее база находилась в другой директории, перенесите её при остановленном боте.
- Месячная статистика накапливается по датам после обновления. Ранее стёртые ежедневными сбросами данные восстановить невозможно.
- Запускайте один экземпляр polling-бота на одну базу. Блокировка составных операций рассчитана на один процесс.
- Файлы `*.session` и `*.session-journal` не должны попадать в Git. Если авторизованная Telegram-сессия уже публиковалась, отзовите её: исключение файла из новых коммитов не удаляет его из истории.
